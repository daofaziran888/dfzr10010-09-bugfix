# 湖仓一体化治理平台

面向数据架构师的湖仓一体化治理平台。覆盖数据湖表格式管理、Iceberg/Hudi表优化、小文件合并、数据压缩策略、元数据服务、表快照管理、数据分支合并与数据回滚恢复的完整湖仓治理链路。

这是一个前后端分离的管理平台：前端 Vue 3 + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 业务模块

| 模块 | 目录 | 业务对象 | 主要字段 |
| --- | --- | --- | --- |
| 湖表格式管理 | `tablefmt` | 表格式配置 | 配置编号、表名称、格式类型、分区字段、主键字段、排序字段、版本保留 |
| 表结构字段数据集 | `fieldcheck` | 字段数据集/字段核对清单 | 数据集编号、表名称、版本号、来源、版本状态、字段清单 |
| 小文件合并 | `compact` | 合并任务 | 任务编号、目标表名、文件范围 |
| 数据压缩策略 | `compress` | 压缩配置 | 配置编号、目标表名、压缩算法 |
| 元数据服务 | `metadata` | 元数据表 | 表编号、表名称、字段清单 |
| 表快照管理 | `snapshot` | 快照记录 | 快照编号、表名称、快照时间 |
| 数据分支合并 | `branch` | 分支记录 | 分支编号、表名称、分支类型 |
| 数据回滚恢复 | `rollback` | 回滚记录 | 记录编号、表名称、回滚版本 |
| 分区演进管理 | `partition` | 演进计划 | 计划编号、表名称、当前分区 |
| 表优化管理 | `iceberg` | 优化任务 | 任务编号、表名称、优化类型 |
| 数据目录同步 | `catalog` | 同步作业 | 作业编号、源路径、目标目录 |
| 数据过期清理 | `cleanup` | 清理策略 | 策略编号、目标表名、过期条件 |
| 湖存储配额 | `quota` | 配额配置 | 配置编号、存储空间、表数量上限 |
| 湖仓血缘追踪 | `lineage` | 血缘记录 | 记录编号、上游表名、下游表名 |

| 数据迁移管理 | `migrate` | 迁移任务 | 任务编号、源表名、目标表名 |

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。

## 湖表格式配置与表结构字段数据集联动

- 登记表格式配置时，分区字段、主键字段、排序字段、版本保留与基础字段一起完整落库，
  重新打开草稿保存时全量回写，不再出现登记后字段丢失。
- 配置状态只能按 `草稿 -> 已创建 -> 已优化 -> 已废弃` 顺序推进：草稿不能跳过创建直接
  优化；执行创建表前会强校验分区字段、主键字段、版本保留，缺一项即拒绝，避免下游按
  错误字段建表。
- 创建表成功后按显式配置生成首版「表结构字段数据集」（`field_dataset`），下游字段目录
  只沿用当前数据集版本；刷新字段清单与显式配置冲突时开新版本并接管“当前”身份，同表
  永远只有一份 `是否当前=true` 的可追溯字段定义。
- 数据集版本只能按 `待确认 -> 已确认 -> 已发布` 顺序推进，不能跨级、不能回退；旧发布
  版本在新版本发布时自动归档。
- 数据目录同步（下游字段目录）先兼容没有数据集的历史记录（登记为待核对），再核对版本
  边界：禁止绑定已归档/非当前版本（即禁止回退已发布版本），并用当前数据集的分区信息
  校验线上表。
- 各业务链路（合并、压缩、快照、回滚、优化等）的处理结果与目录分区校验结果都按
  「表 + 数据集版本 + 来源模块 + 核对项」归集到同一份「字段核对清单」
  （`field_checklist`），配置详情与字段详情两个入口读到的是同一批结果，重复处理只
  更新不新增，杜绝重复显示和残留变更。
